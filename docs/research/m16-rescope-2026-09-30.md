## The fact we design around

The `confidence` scalar measured OOS AUC **0.522** against a pre-registered **0.55** gate for
predicting trade outcome (M18 expanding walk-forward, n_eval = 1,236, BTC/ETH/SOL 5m,
2022-01→2026-05; [findings](M18-allocator-backtest-findings-2026-06-29.md)). Every sibling input
sits 0.47–0.53. So `confidence` is not a cross-strategy win predictor and this memo does not
re-propose that.

One observation shapes the candidates. Each strategy builds `confidence` from its own geometry,
so its scale is not shared: breakout depth in `trend_donchian.py:412`, pierce depth in
`fade_breakout_4h.py:280`, a blend of trend strength and pullback quality in
`htf_pullback_trend_2h.py:379`. A pooled AUC across strategies mixes incomparable scales and
would read near 0.5 even if the score ranked well inside every leg. **That is a hypothesis, not a
finding.** M18 never split by leg, so the within-leg question is open, not answered.

## Candidate uses

### 1. Within-leg sizing tilt (most promising — registered)

*Does a trade that enters with relatively higher confidence **for its own leg** earn more R?*
It is the use M18 does not rule out, and it is what the live reductive conviction arm
(`CONVICTION_SIZING_MODE=apply`, `bybit_1`, demo) already assumes. C1 graded that arm on portfolio
max-drawdown over a net-negative population (BTC better, SOL worse, ETH n=12), not on the prior
question. Candidate 1 tests that prior question.

- **Population:** the 28 legs above, trades with ≥ 20 earlier trades in their leg. Expected ≈ 2,300;
  that figure is an inference from the census, not a measurement of the statistic.
- **Metric:** pooled Spearman of the past-only within-leg confidence percentile against full-cost
  net R, both centred within (leg, entry-month) strata. The centring removes the likeliest false
  positive, a month in which every leg's confidence and R are both high.
- **Pass bar (registered before the run):** n_eval ≥ 1,500 **and** ρ ≥ +0.08 **and** stratified
  permutation p ≤ 0.05 (10,000 shuffles) **and** ρ ≥ +0.04 with each strategy family left out in
  turn **and** a budget-matched tilt (size × (0.5 + percentile)) gains net R on the ledger.
- **Minimum n:** 1,500. At that n the minimum detectable ρ is 0.072, below the 0.08 bar, so a PASS
  cannot be a detectable-but-trivial correlation. `n < 1,500` reads `indeterminate`, never FAIL.
- **What PASS buys:** a per-leg, budget-matched, path-dependent A/B (the existing `c1-conviction-ab`
  harness). Not a config change. The ledger-level tilt cannot see margin or drawdown.
- **What FAIL buys:** the within-leg use is closed-negative. The demo reductive arm then has no
  evidential basis, which I'd raise to the operator as a Tier-3 retirement decision. I am not making it.

### 2. Veto / filter on the lowest decile (secondary — not gated)

*Does the bottom decile of within-leg confidence lose money that the rest does not?* It needs the same
data and the same percentile, so it is a second readout of unit 601, not a second unit: bottom-decile
n ≈ 230 and rest-of-book mean net R are printed in `informational`. **It gates nothing.** A second
gating test on the same rows would be a second look without a second bar. If candidate 1 passes and
the decile contrast is large, register the veto as its own unit with its own bar. Note that several
strategies already carry a `min_confidence` floor (`trend_donchian.py:418`,
`htf_pullback_trend_2h.py:380`), so a lower tail is partly truncated already.

### 3. Regime or vol proxy (not recommended)

M18 already tested regime context as a ranking feature: `+regime` 0.5110 versus market-only 0.5114,
no lift. The regime-selectivity skill's Rule 1 bars a gate on a healthy book, and the vol verdict
already has a dedicated ML head (`REGIME_ML_VERDICT_MODE=use`, BTC). A confidence-as-vol-proxy would
have to beat that head before it earned a cell. No trade row in any `source_run` ledger carries a vol or regime label (the only matching field is
`regime_weight`), so I'd be inventing data. Not registered.

### Excluded: ordering tie-break

Already measured. The ranking-key A/B (2026-09-08, `REPORT.txt`) has `confidence_first` at
Δ net R +701.7 over a random tie-break on 1,130 contested trades, **p = 0.097 against a Bonferroni
α of 0.0167, so it does not clear**, and it is `not_preferred` head-to-head against `priority_first`
(p = 0.583) and `recent_pnl_first` (p = 0.937). The control there is also a −1,016 R population with
a per-tick re-roll (331 flips against 18–20), so part of its deficit is instability. Not re-run.

## Limits, stated so the result is read correctly

- **Not edge.** The committed ledgers carry `parameter_selection: not_established`; a PASS is Stage-0
  evidence that a mechanism exists, nothing about profitability.
- **Cross-leg dependence.** Trades in one month share a market, so effective n is below the row count.
  Hence the (leg, month) strata and `expected_n` set under the row count.
- **Confidence is read at entry.** The past-only percentile uses earlier trades' confidences only, never an
  outcome, so it cannot leak. Legs shorter than 40 trades are excluded and listed in the output.
- **Smoke tests are synthetic.** `tests/test_m16_within_leg_confidence.py` plants a signal, a null, a thin
  population and an empty one. The script was deliberately **not** run on the committed ledgers.
