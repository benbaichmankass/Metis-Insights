### ⚠ Analysis trap in this log — read before aggregating it

Each apply emits **two** rows: the `kind:"apply"` row, then a plain `would_be_size`
annotate row microseconds later whose **`risk_based_qty` is the ALREADY-REDUCED
qty** (e.g. 5.869→1.595 apply, then a row reading `risk_based_qty: 1.595,
would_be_qty: 1.595`). Anyone computing "mean reduction" over all rows halves the
answer, because every second row shows 0%. **Filter to `kind=="apply"` before
aggregating.** This is a sub-class-B shape (an implicit input substitution the
output does not mark) and it is why the table above is restricted to apply rows.

## 4. Both decision soaks are dominated by real-vs-prop VARIANT pairs

This is the bigger finding, and it applies to **`allocator_soak` too**.

In the `allocator_soak` tail every row is `n_candidates: 2`, and 7 of 8 pairs are a
strategy against **its own prop variant**:

- `trend_donchian_eth` vs `trend_donchian_eth_prop` (×5)
- `trend_donchian_sol` vs `trend_donchian_sol_prop`
- `eth_pullback_2h` vs `eth_pullback_prop_2h`
- (one genuine pair: `ict_scalp_xrp_5m` vs `ict_scalp_xrp_15m`)

The variants differ *only in TP* — same symbol, same side, near-identical entry/SL
and confidence. The prop variant's tighter TP mechanically scores lower under
`ev_net_r`, so the allocator "prefers" the real variant and `agree:false` fires. E.g.
2026-08-01T18:26: identical short, entry 1854.04 vs 1854.05, confidence 0.6125 vs
0.6106 — scores 7.806 vs 3.172, logged as **regret 4.634**.

**Consequence: the M18 allocator regret statistic is not measuring strategy
selection.** It is largely measuring "the prop TP is tighter than the real TP," which
is a config fact, not EV left on the table — a prop ticket and a real order are not
substitutes competing for the same capital. The
`docs/research/M18-allocator-backtest-findings-2026-06-29.md` conclusion (EV
selection does not beat dumb priority; ranker OOS AUC ≈ 0.51) is **unaffected in
direction** — this makes the soak's *apparent* disagreement rate look better than
the real one, so it strengthens rather than weakens the case for keeping P2/P3
parked. But `mean_regret` and `disagree_pct` as currently computed should not be
quoted without excluding variant pairs.

`head_p_win` is `null` on every candidate, confirming the parked P_win input.
