## Building practices — the stopping rules

These bind every session, not just Phase 0.

### Verification is proportional to blast radius

| the change touches | what it must carry |
|---|---|
| **live order path · money-DB writes · risk/sizing · account mode** | falsification, a live positive control, the population stated. No shortcut. |
| **runtime observability that can refuse or resize a trade** | a test shown to fire on a synthetic positive |
| **notifications · docs · CI wiring · research tooling** | a unit test shown to fire. **Stop there.** |

**The rule that was missing: stop at the level where a wrong answer costs money.**
A swallowed Telegram is worth a unit test, not two real operator pings. If you are
verifying the verifier, you have gone one level too far — unless the thing being
verified can move money.

### One copy of every fact

A fact lives in exactly one place and is **derived**, never restated. On
2026-08-21 three "canonical" documents gave the required-check list as **15, 9 and
3**; only the last was true. Prefer reading branch protection, the config, or the
code over mirroring it.

### One session at a time

Serial unless the work is provably disjoint. Three concurrent sessions spent a
visible fraction of their effort on merge slots, board tail proofs and shared-file
three-way reconciliations. `session-coordination` still governs when concurrency
is genuinely warranted.

### Open PRs non-draft

Flipping draft→ready **after** CI passes re-runs every required check on the same
commit and leaves two same-SHA context sets, so `get_check_runs` can no longer be
read by name and conclusion alone — you must compare `started_at`. Cost ~12
minutes on #10109.

### Filing has to cost something

The three backlogs hold **984 rows**. ⚠️ **The open count in the previous version
of this line — "378 open (health 777/317 · performance 105/39 · ml 102/22)" — is not
reproducible, and neither is any other single number.** Measured 2026-08-21T19:5xZ on
`1b05353`:

| reading | count | what it is |
|---|--:|---|
| `status == "open"` exactly | **121** | health 108 · performance 10 · ml 3 |
| `status == "kept_open"` | **241** | reviewed and deliberately held |
| anything not in a terminal set | **410** | the widest defensible reading |

**The cause is that `status` is uncontrolled free text.** The health file alone carries
**41 distinct status values**, several of which are whole sentences —
`"resolved (guard); follow-up OPEN, see resolution_criteria (3)"`,
`"code fix shipped; DATA REPAIR still open (52 rows written degraded)"`,
`"bybit_measured_clean_alpaca_unmeasurable_13_positions"`. Each was an honest attempt to
say something a two-state field could not hold, which is the **collapsed-state** class
this repo already names — the field could not express the state, so the state went into
prose the counter cannot read.

**This is why 333, 378 and 121 have all been quoted this month and each was right under
some filter.** It is also the reason Phase 0.1 has no machine-checkable done-condition
today: *"an open count you can defend row by row"* presumes the open set is computable,
and it is not. Normalising the field is therefore 0.1's **first step**, not a separate
item — see below.

One measured piece of good news, since the previous line implied otherwise: **0 open rows
lack `resolution_criteria`.** An earlier count of 71 was taken over a wider status filter
and does not hold on the strict set.

"Filing is cheap" is true and is exactly why the file grew past the point anyone reads it.
A row nobody will action is indistinguishable from noise and, worse, reads as *covered*.
