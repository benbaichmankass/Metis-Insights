# Bot API reference — routes, response shapes, and their caveats

> **What this is.** The per-endpoint reference for the FastAPI on `:8001`
> (`ict-web-api.service`): every route's return shape, the file or table it
> reads, and the ⚠️ read-this-before-you-trust-it caveats attached to
> individual fields. **Split out of the root `CLAUDE.md` on 2026-09-02**
> because it is *lookup* material — you need it when you touch a route, not
> before your first tool call, and it was 35.8% of the one file that reaches a
> session before it acts.
>
> **The rows moved VERBATIM, warnings attached.** Nothing was summarised,
> shortened, or dropped. Most of the ⚠️ blocks here exist because an earlier
> version of the same row was stale *in the dangerous direction*; separating a
> row from its correction would have been worse than leaving both in place, so
> the correction travels with the row.
>
> ## What this file is NOT
>
> - **It is not the tier authority.** [`docs/api-tier-policy.md`](../api-tier-policy.md)
>   is the single source of truth for which routes are Tier 1 / 2 / 2.5 / 3,
>   and `api-tier-policy-guard` **fails CI** for a route under
>   `src/web/api/routers/` with no row there. The `Tier N` notes in the tables
>   below are a convenience restatement; when they disagree with
>   `api-tier-policy.md`, that file wins. **Do not let this become a third
>   inventory** — a new route needs its row *there*, and a row here only if the
>   route has a shape or caveat worth stating.
> - **It is not the runtime gate.** The gate is the actual
>   `Depends(require_session)` / token check wired in each router. *Field beats
>   comment*: if a row here disagrees with the code, the code is the truth and
>   this file gets fixed.

Registered with `collapsed-state-guard` as `db_explorer.filter_state`. |
| `GET /api/bot/trades/closed?limit=N&offset=N&since=ISO_TS&account_id=X&include_paper=BOOL` | `ClosedTrade[]` (#557) — each row carries `accountClass` (`"paper"`/`"real_money"`) plus legacy `isDemo`, `assetClass` (coarse reporting bucket for symbol-group filtering), and **`pnlProvenance`** (`"measured"`/`"estimated"`/`"fabricated"`/`"unverified"`, null when `realizedPnl` is null — the per-row measured-vs-manufactured grade from `src/runtime/provenance.py::classify_pnl`; consumers render fabricated/unverified with a caveat, P0.3 2026-07-31), and **`journalTrust`** (`"known_divergent"`/`"no_record"`/`"unreadable"` — added 2026-08-26). ⚠️ **`journalTrust` and `pnlProvenance` answer different questions and neither substitutes for the other**: `pnlProvenance` grades how THIS ROW's number was derived, `journalTrust` grades whether the ACCOUNT's rows reconcile with the venue's wallet at all. A row can be `measured` on an account that does not reconcile — `bybit_2` is exactly that (wallet-truth −$262.52 against a per-row journal sum ~8× smaller). ⚠️ **`no_record` IS NOT "trusted"**: `comms/broker_truth_ledger.json` is populated BY HAND from an operator's venue export, so an absent record means nobody has reconciled that account, never that it reconciles; `unreadable` means we could not look. A consumer that renders anything but `known_divergent` as a clean bill of health has reintroduced the bug. Why it exists: the ledger recorded `bybit_2`'s divergence from 2026-07-13 and its ONLY consumer was its own route — nothing on the journal READ path consulted it, so on 2026-08-26 a session quoted that account's closed BTC trades as "+$0.88, flat" and the operator had to correct it from the venue UI (`BL-20260826-JOURNAL-READS-DO-NOT-CONSULT-THE-BROKER-TRUTH-LEDGER`). Resolved through `src/runtime/broker_truth.py::journal_trust_map` — ONE ledger read per request, graded per row. **Paper rows are excluded by default**; `include_paper=true` adds them (`include_demo` is a deprecated alias; effective = `include_paper OR include_demo`); `account_id=X` returns only that account (and always wins over the include flags). ⚠️ **THIS ROUTE SERVES THE WINDOW OR REFUSES IT WITH A REASON — IT NEVER RETURNS A BARE `[]` TO MEAN "SOMETHING WENT WRONG"** (2026-09-06, MI-144, `BL-20260906-TRADES-CLOSED-SILENTLY-RETURNS-EMPTY-ABOVE-LIMIT-200-AND-FOR-ANY-SINCE`). It previously returned `[]` from FOUR `except` paths — missing DB, locked DB, `sqlite3.Error`, blanket `Exception` — and its docstring advertised that as a feature. This is the route a performance review grades from, so an unreadable journal rendering as *"no closed trades yet"* is a clean, confident, WRONG negative: § "Collapsed states" applied to a whole endpoint, where *we could not look* and *we looked and there is nothing* had one representation. Now **HTTP 503** with a machine-readable `detail.reason` ∈ `db_file_missing` · `db_operational` · `db_read_failed` · `unexpected_error` — four states because they have four different remedies (a busy DB is a RETRY, a schema mismatch is a DEPLOY). A `200` + `[]` now means exactly one thing: *we looked and there is nothing*. ⚠️ **`limit` above `MAX_LIMIT` (200) returns HTTP 422 naming the bound — that is a refusal WITH a reason and is CORRECT.** A caller that coerces a non-200 body into `[]`/`0` will read it as an empty window; that is what produced the original "limit=400 → 0 rows" report, which did NOT reproduce (MEASURED 2026-09-06: 201/400/800/2000 all 422 with `ctx.le=200`; `since=2026-09-01` → 142 rows). **`offset` (added 2026-09-06) is what makes the window above one page REACHABLE** — the cap bounds ONE PAGE, not the reachable history, so "the last 400 closes" is two calls. Raising the cap was never the fix; the defect was the silence and the unreachable window. **Two response HEADERS make truncation distinguishable from exhaustion**: **`X-Total-Count`** (rows matching the filters BEFORE `limit`/`offset`) and **`X-Has-More`** (`"true"`/`"false"`). Without them a full page and a complete answer render identically. They are headers rather than a body wrapper because the SPA's `ClosedTrade[]` contract is an ARRAY — changing the body shape to carry metadata would break the only live consumer. | `trade_journal.db::trades` filtered to closed + non-backtest, joined to `order_packages` for the closed-at proxy |
| `GET /api/bot/performance?window=24h\|7d\|30d\|all` | `{window, since, error, journalTrust{readState, accountsKnownDivergent, accountsUnrecorded, accountsUnreadable}, totalTrades, wins, losses, winRate, totalPnl, expectancy, totalR, expectancyR, rTradeCount, rCoverage, rBasis{declaredInitial, storedStop, refusedWrongSide, noBasis}, rProvenance{contaminated, confirmedInitial, unverified, noBasis, tightenedVsDeclared, declaredRiskRecords, ratioBar}, bracketOutcome{reachedSl, reachedTp, midBracket, gradeable, reachedRatio, noExitPrice, priceNotMeasurable, noBracketRecord, directionUnreadable, excludedReduceLeg}, pnlCoverage, totalPnlMeasured, pnlMeasuredCount, pnlEstimatedCount, pnlFabricatedCount, pnlUnverifiedCount, profitFactor, maxDrawdown, perStrategy:[{name, trades, wins, winRate, totalPnl, totalPnlMeasured, expectancy, totalR, expectancyR, rTradeCount, rBasis{…}, rProvenance{…}, pnlMeasuredCount, pnlEstimatedCount, pnlCoverage}], perAssetClass:[{assetClass, trades, wins, winRate, totalPnl, expectancy, totalR, expectancyR, rTradeCount}], perSymbol:[{symbol, assetClass, trades, wins, winRate, totalPnl, expectancy}], perExitPath:[{exitPath, trades, wins, winRate, totalPnl, totalPnlMeasured, pnlMeasuredCount, pnlEstimatedCount, pnlCoverage, labelAttestedCount, labelRefusedCount, labelUnresolvedCount, labelUnattestedCount}], equity:[{t, cum}], paper:{…same shape…}, paperPortfolio:{…same shape, scoped to `paper_role: portfolio` accounts…}, demo:{…back-compat alias of paper…}}` — windowed aggregate trade analytics computed **in SQL over the full history within the window (uncapped)**. The R-metrics normalise pnl by each trade's own risk so cross-instrument trades compare on one axis (null when risk is unknown; `rCoverage`/`rTradeCount` report how much of the window is R-measured — never a raw-pnl fallback). `profitFactor` (gross profit / gross loss) and `maxDrawdown` are **null** (not 0) when uncomputable. **`totalPnlMeasured`** (headline + per-strategy, added 2026-08-01) is the sum of `pnl` over **MEASURED+ESTIMATED** provenance rows only — the honest figure the R4 research→results promotion gate reads INSTEAD of `totalPnl` (which sums fabricated marks); read it beside `pnlCoverage` (a leg below the coverage floor is judged on too thin a measured sample and the gate abstains). ⚠️ **THE COUNT AND THE SUM ARE OVER DIFFERENT POPULATIONS, DELIBERATELY** — `pnlCoverage`/`pnlMeasuredCount` are **MEASURED-only** (the canonical `provenance.coverage` population; ESTIMATED is *not* "covered"), while `totalPnlMeasured` sums **MEASURED+ESTIMATED**. The R4 gate depends on exactly that asymmetry (`research_results_gate.leg_verdict`: a MEASURED-only floor decides whether the wider measured sum is trustworthy at all), so **neither may be "harmonised" to match the other**. **`pnlEstimatedCount` is published per-strategy (added 2026-08-11) so the pair RECONCILES** — without it a correct row read as a broken one: `trend_donchian_avax_4h` returned `pnlCoverage: 0.0` beside `totalPnlMeasured: -5415.17` (both rows ESTIMATED, so the sum equalled `totalPnl` exactly) and the only available inference was "the measured sum falls back to the raw sum", which is false; a second row (`pairs_bnb_btc_a`, -2.961 vs -211.08 at the same 0.0 coverage) is what ruled it out. 2 of 51 live strategy rows. Replaces consumer-side rollups over the 200-row `/trades/closed` cap (which pinned the retired Android app's Performance "Trades" count at 200). Excludes backtest + paper rows like `/stats`; close-time basis is the **epoch-ms-aware** `COALESCE(<closed_at normalised>, op.updated_at, t.timestamp)` (shared `src/web/api/_closed_at.py` — the reconciler-filled close path writes `trades.closed_at` as a raw epoch-ms string, which an unguarded `datetime()` drops from the window; this was the "0 closed trades in 24h while lifetime is non-zero" bug, fixed for `/performance` + `/stats` pnl24h to match `/trades/closed`). Additively returns a `paper` sub-block (and a back-compat `demo` alias) with the same shape computed over paper-account rows, **plus a `paperPortfolio` sub-block** (same shape) scoped to just the live-portfolio-mirror paper accounts (`paper_role: portfolio` — `bybit_portfolio`/`alpaca_portfolio`, S-PAPER-PORTFOLIO 2026-07-16) so a consumer's "Paper" view can show the real portfolio without the full soak roster; falls back to the all-paper `paper` block when no portfolio accounts are declared. **`perExitPath` (added 2026-08-25) is coverage cut by EXIT PATH, and it is the cut that makes a structural failure visible** — `pnlCoverage` was published globally and per-STRATEGY only, and a global 42.9% averages a path at 96.9% together with a path at **0.0%** into a number that describes neither. Sorted **worst-coverage first, not best PnL**, because the point is to surface the unmeasured paths rather than rank the profitable ones. It ships in the `paper` and `paperPortfolio` sub-blocks too, which is load-bearing rather than incidental: the entire **pairs sleeve runs on a paper account**, so a real-money-only cut would not show it at all. Measured live 2026-08-25, window=all — real money 14 paths, `netting_attributed` / `intent_reduce` / `stuck_strategy_watchdog` at 0.0; paper 16 paths, with `pairs_revert` (44), `pairs_stop` (40), `pairs_half_open_cleanup` (31) and `pairs_timeout` (2) **all at 0.0** — 117 closes on a sleeve where not one exit price was ever confirmed by the venue (`BL-20260825-EXIT-PROVENANCE-IS-STRUCTURED-BY-EXIT-PATH-SIX-PATHS-AT-ZERO`). ⚠️ A path at `pnlCoverage: 0.0` with a non-zero `pnlEstimatedCount` has been measured and graded ESTIMATED; one at 0.0 with BOTH counts zero has never been measured at all. Those are different states and the two counts are what separates them — do not read the coverage figure alone. **The four `label*Count` fields (added 2026-08-26, GATE 0 / G1) grade the bucket's own KEY, not its money** — `pnlCoverage` says how much of this path's PnL is a measurement, these say whether the rows belong in this path at all. The distinction is load-bearing because `exit_reason` IS the bucket key and is exactly the field `BL-20260822-EXIT-REASON-FROZEN-WHEN-PRICE-ARRIVES-LATE` shows wrong for the majority of the rows it is applied to: the no-record close path hard-codes `reconciler_filled` before any price exists, and until #10262 nothing re-ran the classifier once a price arrived. Four states, never collapsed — `attested` (the classifier ran and resolved) · `refused` (it ran and DECLINED, because the price it would have compared was FABRICATED) · `unresolved` (it ran; the price sat mid-bracket — a genuine non-bracket close) · `unattested` (it never ran). They sum to `trades` by construction, so the partition is checkable rather than trusted. ⚠️ **NO RATIO IS PUBLISHED, DELIBERATELY, and one must not be added**: an AUTHORED path (`sl_cross`, `tp_cross`, `pairs_*`, `netting_attributed`) is written by the producer that closed the trade and never reaches `_classify_broker_exit`, so ~100% unattested is CORRECT there and a `labelCoverage` of 0.0 would read as a gap on a path that has none — the read-a-number-off-the-wrong-population error the gate exists to stop. The figure that matters sits on the reconciler-derived buckets. Measured live 2026-08-26 — population: `trades` with `exit_reason='reconciler_filled'`, n=593, all `status='closed'`, of 5,056 total rows — **562 of the 589 gradeable rows (95.4%) carry no `exit_reason_source` at all**, and only 53 rows in the whole table have ever reached the classifier. **`journalTrust` (added 2026-08-26) is the account-level sibling of `pnlCoverage`**: coverage says how much of `totalPnl` is a MEASUREMENT, this says whether the ACCOUNTS those rows belong to reconcile with the venue's wallet at all. Scoped to the accounts actually IN the window, so a paper-only window does not carry a real-money caveat, and it ships inside the `paper`/`paperPortfolio` sub-blocks too. ⚠️ **`accountsUnrecorded` is NOT `accountsTrusted` and is deliberately not named that** — the ledger is populated BY HAND from an operator's venue export, so an unrecorded account means nobody has reconciled it; `readState` ∈ `read`/`absent`/`unreadable` says whether we obtained the ledger at all, and `absent` on the live VM is a DEPLOY failure, not a data state. The key is present on the empty/errored envelope too — a key that vanishes makes a consumer branch on absence, and absence is not one of the states. Zeroed envelope (HTTP 200, `error` set) on unknown window / DB error. Tier 1 ⚠️ **`totalR` / `expectancyR` CHANGED BASIS ON 2026-09-06 (MI-144) AND ANY R FIGURE QUOTED BEFORE THAT DATE IS ON THE OLD, CONTAMINATED ONE — do not compare across the change.** `trades.stop_loss` holds the **FINAL trailed** stop (`order_monitor._apply_update` mirrors every confirmed amend onto the row, correctly, because `/api/bot/positions` must show where the stop IS), while R is *defined* against entry-time risk — so a trade trailed through breakeven collapsed `|entry − stop|` and `pnl / risk` exploded; and `abs()` turned a stop stored on the WRONG SIDE of entry into a small positive risk instead of refusing it. MEASURED 2026-09-06 (live journal via `/api/bot/db/table/{trades,order_packages}`, 5518 + 4435 rows; the endpoint's own totals reproduced first as a positive control): the **30d real-money window published `expectancyR +0.9818` while it LOST money** (`totalPnl −3.6266`, `profitFactor 0.9507`), with 12 of 39 rows (30.8%) carrying 117.1% of that R; `paperPortfolio` published **+0.6253 on a book down $11,244.87**; over the whole journal (n=1287) **104 contaminated rows — 8.1% — carried 96.6% of `totalR`**, single-row max `R = +3672.3`. The denominator is now the trade's **declared initial risk** (`order_packages.meta::risk_per_unit`, which no trailing amend can reach) where one exists, the stored stop where none does and the stop is not PROVEN wrong-side, and a **REFUSAL** otherwise. **`rBasis` says which of those four every row used**, so no published R is over an unstated population: `rTradeCount == declaredInitial + storedStop` by construction, `refusedWrongSide` + `noBasis` count in NEITHER the R numerator nor its denominator, and the four sum to `totalTrades`. ⚠️ **A non-zero `refusedWrongSide` is not a data-quality footnote** — it counts rows whose R used to be a finite number produced by `abs()`-ing an impossible risk, so the OLD figure for that window was wrong, not merely noisy. ⚠️ **A high `storedStop` share is NOT clean**: it means no signal-time record exists, so those denominators are still the CURRENT stop and a trailing amend can still move them — they are simply not PROVABLY wrong. Read it beside `rProvenance.unverified` (*we could not look* — the largest bucket by construction, and emphatically not "clean"). ⚠️ **`expectancyR` and `profitFactor` need not share a sign, and forcing agreement would be fitting the instrument to a desired answer** — R weights each trade by its OWN risk, USD does not. On the paper block the corrected R (−0.1323) disagrees with `profitFactor` 1.4066 because that block's entire +$124,653 net rests on ONE row (id 4773, `ict_scalp_mgc_15m` MGC, **+$249,185**, `pnlProvenance: estimated`). **`bracketOutcome` (added 2026-09-06) answers "are trades ending at their brackets?" from the PRICE, not from the label.** `perExitPath` above buckets on the STORED `exit_reason`, which is written ONCE at close time — and for the largest close path that is the one moment the answer cannot be known (the no-record fallback hard-codes `reconciler_filled` with `exit_price` still NULL; #10262 re-runs the classifier when the price arrives, but on ONE path and FORWARD only). This re-derives the verdict from the recorded exit price against `order_packages.sl`/`.tp` using the same conservative inequality `order_monitor._classify_broker_exit` uses (`src/runtime/bracket_outcome.py`, pinned to it by a test). ⚠️ **NOTHING IS WRITTEN BACK** — a producer-AUTHORED label (`vwap_cross`, `pairs_stop`, `exit_head`) records a real decision, and a journal re-label is Tier-2. ⚠️ **`reachedRatio`'s denominator is `gradeable`, NEVER `totalTrades`**, and it is `null` — never `0.0` — when nothing could be graded; the other states are *we could not look* (`noExitPrice`, `directionUnreadable`), a REFUSAL (`priceNotMeasurable` — a FABRICATED exit price compared to a bracket manufactures a verdict out of unrelated price action), or NOT APPLICABLE (`noBracketRecord`, `excludedReduceLeg`). ⚠️ **`midBracket` is an OUTCOME, not a defect** — `vwap`, `exit_head` and `time_decay` exit deliberately before a bracket. MEASURED 2026-09-06: **real money n=424, 420 gradeable, 228 (54.3%) reached a declared bracket — 187 sl vs 41 tp, a 4.6:1 stop:target ratio — against a stored label reading `sl|tp` on only 127 (30.0%)**; all accounts n=1287, 430 of 1125 gradeable (38.2%) vs a stored 19.5%. ⚠️ **Quote the real-money row, not the all-accounts one, until `BL-20260906-PAIRS-LEGS-GRADED-AGAINST-A-PER-LEG-BRACKET-THAT-MAY-NOT-BE-THEIR-STOP` is settled**: all 301 gradeable `pairs_*` legs grade `midBracket` (0 reached, on all four strategies), and a pairs leg stops on the SPREAD rather than either leg's own price, so the per-leg yardstick is probably inapplicable there. | `trade_journal.db::trades` LEFT JOIN `order_packages` |
| `GET /api/bot/order-packages?limit=N&since=ISO_TS&strategy=X&include_paper=BOOL` | `{rows:[{orderPackageId, createdAt, updatedAt, strategy, symbol, assetClass, direction, entry, sl, tp, confidence, status, closeReason, linkedTradeId, pnl, tradeStatus, accountClass, isDemo, signalLogic, meta, modelScores, claudeScore}], count, claude_log_present}` (`assetClass` = coarse reporting bucket for symbol-group filtering) — **decision-level** view (one row per order package = the bot's actual decision). **`pnlCoverage` / `pnlMeasuredCount` / `pnlEstimatedCount` / `totalPnLMeasured`
(added 2026-08-26, GATE 0 / G3) state how much of `totalPnL` was ever a
MEASUREMENT.** `/stats` is the FIRST number both apps render and it published a
sum and a rate over journal `pnl` with no provenance at all, while
`/api/bot/performance` has carried `pnlCoverage` since 2026-07-31. ⚠️ **The
count and the sum are over DIFFERENT populations, deliberately, and the
definitions are copied from `/performance` rather than re-derived** —
`pnlCoverage`/`pnlMeasuredCount` are MEASURED-only, `totalPnLMeasured` sums
MEASURED+ESTIMATED; two surfaces reporting the same population under the same
key must not disagree, and neither may be harmonised to the other. ⚠️ **`None`
means WE COULD NOT LOOK, never `0.0`** — an older journal with no `notes`
column is ungradeable, and reporting zeros there would assert an observation
nobody made; a MISSING DB file is instead "no trades yet" (the same reading
`_pnl_stats_for` already takes), so its COUNTS are real zeros while the ratio
stays `None`, because a coverage ratio over an empty population does not exist.
The keys are always PRESENT — a key that vanishes makes a consumer branch on
absence, and absence is not one of the states. The block is computed
**outside** the raising path: `_pnl_stats_for` 503s on a broken schema because a
fabricated `pnl24h: 0` reads as "no trades today", but a failed provenance read
leaves the money numbers intact and only the caveat missing, so it degrades to
nulls rather than taking the route down. Measured live 2026-08-26 — population:
closed, non-backtest, `pnl NOT NULL`, real-money, **n=431** — coverage
**0.768**, with `totalPnL` moving **−$23.22 → −$45.63** restricted to
measured+estimated. ⚠️ **That coverage figure is population-specific and must
not be quoted as the journal's**: the same classifier reads **0.425** over all
accounts (n=1,187) and **0.257** over the package-joined population the
2026-08-26 workplan cites as fact 2 (n=806, reproducing its 25.6%). The case
for this block is the SUM nearly doubling, not the coverage being alarming —
and the real-money win rate moves only **0.1pp**, so do not carry the
workplan's "win rate moves 9 points" across to this surface; that contrast is
between the ESTIMATED and MEASURED buckets on a different population.

The top-level `pnl24h` / `totalPnL` / `openTrades` / `winRate` are **real-money
only** — paper rows are excluded (account_class-authoritative, is_demo
fallback). **Real and paper performance are never blended** (P4 of the
live-trade management contract, operator directive): the paper-side aggregates
ride in an **additive `paper` sub-block** (same shape) plus a distinct
`paperOpenTrades` count alongside the real `openTrades` KPI, so a consumer
renders the two as separate sections — there is no combined real+paper total
anywhere.
