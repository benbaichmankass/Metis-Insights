⚠️ **CORRECTION — MI-92 / #10904: my DONE post's guard claim was scoped too narrowly, and CI caught it**

Correcting my own post above (`#issuecomment-5522191151`) rather than leaving it to be read as complete validation.

**What I said:** `scripts/ci/run_guards.py --base main` → **PASS 61 · FAIL 0 · SKIP 22**, CI armed and running.

**What then happened:** CI's `guards` job **FAILED**.

**Why — and it was a real finding, not a CI quirk.** `session-brief-guard`:

```
::error::CLAUDE.md's SESSION-BRIEF block is STALE and THIS DIFF introduced it — this
diff changes the registers, so re-rendering is part of it. A session would read
something that is no longer true, which is worse than reading nothing.
Run: python3 scripts/ops/render_session_brief.py --write
```

`CLAUDE.md`'s SESSION-BRIEF is **rendered from `OPEN-ITEMS.json`**, so adding my row without re-rendering left the one surface that reaches a session *before its first tool call* describing a register that no longer matched it. The guard is right and the failure was mine.

**⚠️ THE LESSON, because it will bite the next session the same way — GUARDS ARE DIFF-SCOPED, SO *WHEN* YOU RUN THEM IS PART OF THE RESULT.** I ran them when the diff was `src/` + `tests/` + `pr-landing` only. The OPEN-ITEMS row, the board posts and the pr-request all landed in **later** commits, which widened the diff and made several docs-scoped guards *relevant* that had previously printed `SKIP (not relevant to this diff)` — `session-brief` and `canonical-doc-coherence` among them. **A clean guard run is only a statement about the diff that existed when it ran.** The board/registry commits a session makes at the END are exactly the ones that arrive after validation, which is what makes this trap structural rather than careless.

**Verified, not asserted.** Reproduced locally against the full `origin/main...HEAD` diff — the thing CI actually grades — and it matched CI exactly: **PASS 61 · FAIL 1 · SKIP 21**, one `::error::`, `session-brief-guard`. Fixed with the guard's own stated remedy run verbatim (`render_session_brief.py --write`; 4 insertions / 1 deletion — the DUE count 20 → 21 plus the three rendered lines). Re-run on the full diff: **PASS 63 · FAIL 0 · SKIP 20**, *"All relevant guards passed."*
